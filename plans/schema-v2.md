# dev.avar.me: переход словаря на v2

Дата: 2026-09-30. Статус: план, код и деплой ещё не изменяются.
Общий план: [sources](../../sources/plans/schema-v2/README.md).
Проект схемы: [спецификация](../../sources/av-ru-schema-evolution-plan.md).
Ссылки рассчитаны на соседние локальные репозитории.

## Контракт и ответственность

dev — первая веб-площадка для проверки новой схемы. Сейчас `build.sh`
скачивает JSONL, `src/build_data.py` преобразует старые морфологические поля
и `see_also`. Есть HTML и TMA; проверить обе ветви интерфейса.
Словари не редактировать и не коммитить в этом репозитории.

Этап 1: `literally`, `links[]`, типизированные `forms_dict`.
Этап 2 в том же канале v2: необязательные id, хеш, cefr, origin.
Парсер должен игнорировать неизвестные необязательные поля и не терять
известные сведения молча. Точные типы ссылок утверждаются в sources.

## Последний выпуск v1

- После фиксации последнего старого JSONL пересобрать сайт, записать
  коммит sources и контрольную сумму входа.
- До готовности нового парсера закрепить автоматические сборки за старым
  входом или согласовать безопасное переключение URL. Учитывать cron.
- Сохранить прежний код/вход для отката.

## Реализация v2

1. Добавить явный выбор источника/контракта в `build.sh`. Предлагаемый URL —
   `https://sources.avar.me/data/v2/av-ru.jsonl`. Не заменять общий
   `SOURCES_BASE` для всех словарей: ru-av и другие направления пока v1.
2. В `src/build_data.py` читать `literally` отдельно от `comment`,
   `links` на уровне статьи и значения, формы статьи и значений.
3. Сохранить уточнения цели, омонимы и разрешение по word/forms/
   gender_forms/spelling_forms; не создавать две одинаковые ссылки.
4. Типизированные формы включать в поисковый индекс. Не угадывать класс
   и падеж отсутствующих признаков.
5. В HTML и TMA отображать «букв.» перед `literally`, рядом сохранять
   обычный комментарий. Форматировать типы links по утверждённому словарю.
6. Если меняются выходные чанки или их структура, согласовать формат
   с фронтендом и инвалидировать старый кеш через существующий build_id.
7. Сначала проверить локальную сборку/предпросмотр, затем выпуск по ревью.

## Приёмка и передача

Проверить буквальный перевод с пояснением, несколько связей, омонимы,
две формы одного падежа, формы классов/значений, неизвестные поля этапа 2,
поиск и переход по ссылке. Сравнить число доступных статей с входом.
Проверить обновление страницы со старым localStorage-кешем.
Записать успешный коммит и настройки входа для команды ru, не переносить
её отличия/профиль механическим копированием всего репозитория.

Новых исходных id на первом этапе нет. Не смешивать будущие id статьи
с текущими поисковыми ключами. Публикация требует отдельной команды.
